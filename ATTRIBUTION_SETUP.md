# ANCBuddy Attribution and Commerce Setup

Purpose: operate first-party attribution and Lemon Squeezy reporting without
copying production secrets into this repository or its iCloud-synchronised
parent folder.

## Production Architecture

Project ref: `wryaxqkfpphtzbskfjgi`

- `lemon-order-webhook` records new purchases and their first-party attribution.
- `lemon-commerce-sync` reconciles all orders and aggregate customer/store
  metrics from Lemon Squeezy.
- Supabase Cron calls the reconciliation daily at `04:17 UTC`.
- The Lemon API key exists only in Supabase Edge Function Secrets. Its human
  recovery copy is in Apple Passwords.
- Codex clients on other computers authenticate to the Supabase project and
  query the reporting views. They never receive the Lemon key.

The exact secret inventory and rotation runbook are in
[`docs/SECRETS.md`](docs/SECRETS.md). Never put a real value into a Markdown,
SQL, shell, JSON, screenshot, `.env`, or Codex message in this folder.

## Supabase Runtime Secrets

Set these in **Supabase Dashboard → Edge Functions → Secrets**:

- `LEMON_API_KEY`
- `LEMON_WEBHOOK_SECRET`
- `LEMON_EMAIL_HASH_SALT`
- `LEMON_STORE_ID` only if the API key can access more than one store

Supabase's built-in runtime variables are managed by Supabase. The scheduled
trigger token and URL are generated by the migration inside Supabase Vault as
`ancbuddy_lemon_sync_token` and `ancbuddy_lemon_sync_url`; do not export them.

## Deploy

From `ancbuddy-site/`, after authenticating the Supabase CLI without writing a
token or database password into this repository:

```sh
npx supabase link --project-ref wryaxqkfpphtzbskfjgi
npx supabase db push --linked
npx supabase functions deploy lemon-order-webhook \
  --project-ref wryaxqkfpphtzbskfjgi --no-verify-jwt --use-api
npx supabase functions deploy lemon-commerce-sync \
  --project-ref wryaxqkfpphtzbskfjgi --no-verify-jwt --use-api
```

The production reporting objects are:

- `commerce_dashboard_summary_v`
- `commerce_dashboard_monthly_v`
- `lemon_sync_state`
- `lemon_customer_snapshot`

Only `service_role` can read them. The views use `security_invoker = true`;
anonymous and authenticated browser roles have no read permission.

## Lemon Squeezy Webhook

Webhook URL:

```text
https://wryaxqkfpphtzbskfjgi.supabase.co/functions/v1/lemon-order-webhook
```

Configure in Lemon Squeezy with `node scripts/create-lemon-webhook.mjs`, or manually:

- Event: `order_created`
- Signing secret: same value as `LEMON_WEBHOOK_SECRET`; Lemon Squeezy requires 40 characters or fewer.
- Do not include extra events until needed.

## Verification

- Anonymous browser insert works for `site_events` and `trial_signups`.
- Anonymous browser reads/updates/deletes fail for `site_events`, `trial_signups`, and `lemon_orders`.
- Checkout links include `checkout[custom][session_id]`, `utm_source`, `utm_medium`, `utm_campaign`, `referrer_host`, `landing_path`, and `current_path`.
- A bad Lemon `X-Signature` returns `401`.
- A valid Lemon `order_created` inserts or updates one `lemon_orders` row per Lemon order id.
- `lemon_sync_state.last_status` is `success` after reconciliation.
- Every non-test Lemon order has a recent `api_last_seen_at`.
- `commerce_dashboard_summary_v` reports checkout volume, Lemon-collected tax,
  order-derived revenue, customer totals, and store totals as separate metrics.

The reconciliation endpoint intentionally has Supabase JWT verification
disabled because Cron cannot supply a user JWT. The function instead requires
a dedicated high-entropy Vault token, compares only its SHA-256 hash, and
returns aggregate counts without personal data.
